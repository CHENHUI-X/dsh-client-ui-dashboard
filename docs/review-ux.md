# DSH 看板插件 · UX / 交互 / 信息架构评审报告

> 评审对象:`dsh-client-ui-dashboard`(src/client/DashboardView.tsx、charts.tsx、dashboard.css.ts、locales.ts、metrics.ts;功能总表见 README.md)
> 评审维度:信息架构、可发现性、操作效率、可访问性、实时性、长页面导航。
> 评审方式:代码逐行核对(行号随文标注)+ 专业经验判断;无联网取证。
> 与既往两轮的关系:architecture 轮(三层视图/右侧 mini 目录/时间范围选择器/sparkline/分组子 Tab/导出)与 metrics 轮(成本/循环检测/无进展/工具风暴/上下文锯齿等)中,**已实现或有明确方案的不再重复**;本报告只提"实现后仍然存在的交互缺陷(交互 bug 清单)"与"新角度建议"。为避免重复,右侧竖排 mini 目录、时间范围选择器、散点图等不再列入新建议。

## 第一部分:已实现功能的交互 Bug 清单

按影响排序。每条含:位置(文件:行)/ 现象 / 影响 / 改法 / 工作量。

### B1. 成功请求行在键盘下无法内联展开(键盘路径缺失)
- **位置**:DashboardView.tsx:348-372(chevron `tabIndex={-1}`)、906-918(行 `onKeyDown` → `onRowClick`)
- **现象**:成功行(`jumpMode`)的行内 `Enter/Space` 直接跳转轨迹;唯一展开控件是 ▸ chevron,但它 `tabIndex={-1}` 不在 Tab 序列;行尾 ↗ 按钮也是跳转。→ 键盘用户对成功请求只能"跳走",永远无法展开详情。
- **影响**:可访问性硬伤;与 README"chevron 键盘可达(Enter/Space)"的宣称矛盾(那只对错误行成立)。
- **改法**:① chevron 改为 `tabIndex={0}` 进入 Tab 序列(保留 `aria-expanded`);② 或行内 Enter=展开、双击/↗=跳转。推荐 ①,改动最小。
- **工作量**:小

### B2. 模型时间线圆点焦点环被内联样式屏蔽
- **位置**:charts.tsx:580(`style={{ ..., outline: "none" }}`)vs dashboard.css.ts:194(`circle:focus-visible{outline:2px ...}`)
- **现象**:圆点已 `tabIndex={0}` 可聚焦,但内联 `outline:none` 优先级高于 CSS 规则,`:focus-visible` 被覆盖 → Tab 到圆点无任何可见焦点。
- **影响**:键盘用户无法感知当前位置,与"每个控件保持可见焦点环"的宣称矛盾。
- **改法**:删除内联 `outline:none`,保留 CSS 焦点规则。
- **工作量**:小

### B3. 表格列头在页面纵向滚动时消失
- **位置**:dashboard.css.ts:115(`overflow-x:auto` wrapper)、116-117(`th{position:sticky;top:0}`)
- **现象**:`overflow-x:auto` 使 wrapper 计算为纵向滚动容器,`th` 的 sticky 相对的是 wrapper 的 scrollport;wrapper 自身不纵向滚动,页面滚动时表头随内容一起滚走。README 的"sticky header"仅在横向滚动时成立,纵向翻页后列名不可见。
- **影响**:长会话里滚到第 8 页,用户不知道第 3 列是"输入"还是"输出"——数字表失去列上下文,读错率上升。
- **改法**:**方案 A(推荐)**:wrapper 加 `max-height` + `overflow-y:auto`,让表格自成滚动区,sticky 表头真正吸顶(附"滚动查看更多"暗示);**方案 B**:把列头行移出横向滚动 wrapper,作为页面流内的常驻表头;方案 C:缩窄列宽使多数场景不横向滚动。
- **工作量**:中

### B4. 搜索与筛选组合时的空态文案/引导错误
- **位置**:DashboardView.tsx:746-768;locales.ts zh:205-207 / en:414-416
- **现象**:
  1. `filter === "all"` 但搜索无命中 → 显示 `empty.requestsTable`("暂无请求记录")——数据明明有,误导用户以为没数据;
  2. `filter !== "all"` 且搜索无命中 → 只显示"没有符合当前筛选的请求"+ 清除筛选按钮,不提示"搜索无命中",也没有清除搜索的入口;
  3. 对比:分组视图(883-887)倒是正确区分了 search/空表,说明这是表格视图的疏漏。
- **影响**:排查时最常出现的场景(搜错词/筛错态),反馈却指向错误原因,浪费排查时间。
- **改法**:按 `search` 是否非空分派 `empty.search`;双条件无命中时并列"清除搜索"与"清除筛选"两个动作;文案走 t()。
- **工作量**:小

### B5. JSON 导出忽略搜索词与分组视图(所见非所得)
- **位置**:DashboardView.tsx:259-295(`exportJson` 遍历的是 `filtered`,仅状态筛选)
- **现象**:用户搜索"web_search"后点"导出 JSON",导出的是**该状态筛选下的全部请求**,搜索命中集被无视;"按轮次/按模型/按错误"视图的聚合视角也不生效。按钮 title 文案"导出当前筛选下的请求明细"与行为不符(筛选生效、搜索不生效)。
- **影响**:WYSIWYG 原则破坏;导出的数据与屏幕所见不一致,用户拿去做分析/分享会得出错误结论。
- **改法**:导出基于 `searched` + 当前 `view` 构建 payload,并写入 `search`/`view` 元信息;文案改为"导出当前视图(含筛选与搜索)";顺带在导出文件名中加入筛选标签。
- **工作量**:小

### B6. 运行中表格行位移与翻页内容漂移
- **位置**:metrics.ts:571(`series` 按 seq 降序,最新在前);DashboardView.tsx:302-319(直接 slice)
- **现象**:运行中每落地一条新请求就 prepend 到表格顶部,所有已见行整体下移一行:
  - page>0 时:用户正在读的行/即将点击的行位置漂移,可能点到别的行;虽有"回到最新"横幅,但横幅出现后当前页内容仍在持续漂移;
  - page=0 时:无任何提示(431-434 只在 `safePage > 0` 时置位),最新页同样抖动;
  - 分组视图:无分页无横幅,组内行同样实时位移。
- **影响**:实时性与"阅读/点按"直接互扰,是监控场景最高频的打断。
- **改法**:**方案 A(推荐)**:翻页锚定内容——记录当前页首行 seq,新数据到来时保持该 seq 所在位置不变,新请求只出现在第 1 页,配合已有"回到最新"横幅;page=0 也显示横幅;方案 B:运行中冻结表格(暂停自动更新),提供手动"刷新"按钮。
- **工作量**:中

### B7. 分组视图无翻页/无上限,长会话 DOM 爆炸
- **位置**:DashboardView.tsx:413-428(全量分组)、840-889(全量渲染所有组×所有行)
- **现象**:表格视图有 10/20/50 分页,分组视图却把每组所有行全量渲染;错误按完整 message 分组,长会话组数可能几十个、每组几十行。
- **影响**:行为不一致(用户在同一区块内体验分裂);渲染量大,与 1 秒 tick 叠加会卡;错误分组细碎到不可读。
- **改法**:每组"显示前 N 条 + 展开更多";组数超过阈值时按"错误类前缀"归并;与表格共用同一行上限逻辑。
- **工作量**:中

### B8. 分组折叠状态跨视图串扰
- **位置**:DashboardView.tsx:299-300(`collapsed` 以原始 label 为 key)、413-428(不同视图共用同一 Record)
- **现象**:`collapsed[g.key]` 的 key 是裸 label(模型名 / 错误文本 / "轮次 #N")。在"按模型"里折叠了 `deepseek-reasoner`,切到"按错误"后若某条错误文本恰好同名,组直接被折叠——折叠态跨视图泄漏;且没有"全部展开/收起"入口。
- **影响**:状态不可预期;大量分组时逐组点折叠效率低。
- **改法**:key 加视图前缀(`${view}:${key}`);分组区头部加"全部展开/全部收起"。
- **工作量**:小

### B9. aria-live 每秒重复播报(读屏噪音)
- **位置**:DashboardView.tsx:1170-1190(streamRow `role="status"`、stuck 警告 `role="alert"`)
- **现象**:运行中每秒 tick 重渲染,`role="status"` 的流式行每行都重播报;`role="alert"` 的卡顿警告更是每次渲染都强制打断读屏。
- **影响**:读屏用户每秒被"正在生成…"轰炸,告警反而被淹没。
- **改法**:内容不变则不更新 aria-live 节点(useRef 对比上一帧文本/告警集合);告警仅在**首次出现/跨阈值**时播报。
- **工作量**:小

### B10. 图表悬停浮标无键盘/无 ARIA 替代,数值对读屏不可见
- **位置**:charts.tsx:DonutChart(101-141)、SeriesBars(248-289)、AreaChart(385-432)、RadialGauge(463-472)
- **现象**:所有交互值只出现在 `onMouseEnter` 浮标或 `<title>`;Donut/Area/Gauge 的 svg `role="img"` 无 `aria-label`,SeriesBars 连 role 都没有;键盘无法聚焦任何图表点。
- **影响**:数值信息(每根柱的值、环上每段的值、仪表读数)对键盘与读屏用户完全不可达;`role="img"` 无 label 时读屏只报"图像"。
- **改法**:每个 svg 加本地化 `aria-label`(说明图含义);SeriesBars/AreaChart 每点 `aria-label="请求#N: 值"`;Donut 段可聚焦 + Enter/Space 选中;或为每图提供"数值表"折叠替代视图。
- **工作量**:小-中

### B11. 轮次耗时卡静默截断 12 条
- **位置**:metrics.ts:813-814(`turnDurations` 降序后 `slice(0, 12)`)
- **现象**:超过 12 轮时无任何"还有更多"提示,用户以为会话只有 12 轮。
- **影响**:数据完整性感知错误(与模型时间线的 "+N more" 注记不一致)。
- **改法**:截断时卡内标注"仅显示最近 12 轮"。
- **工作量**:小

### B12. 硬编码英文 aria
- **位置**:charts.tsx:561(`aria-label="model timeline"`)
- **现象**:未走 t() 本地化,中文界面下读屏报英文。
- **改法**:纳入 NS 字典。
- **工作量**:小

### B13. hint "?" 无语义、焦点行为不确定
- **位置**:DashboardView.tsx:67-73
- **现象**:`<span tabIndex={0}>?</span>` 无 role/aria-label,读屏只报"?";是否聚焦即弹 Tooltip 取决于 primitives 实现。
- **改法**:加 `role="button"` + `aria-label`(如"关于{指标}的说明"),或 `aria-describedby` 关联说明文本。
- **工作量**:小

### B14. 跨视图状态保持风险(需集成验证)
- **位置**:DashboardView.tsx:249-300(filter/search/page/pageSize/collapsed/openSeq 全部是组件内 state)
- **现象**:"点击行→跳轨迹→回到看板"是核心流程;若 shell 在切换 对话/轨迹/看板 时卸载非活动视图,所有筛选/搜索/翻页/展开/折叠状态即丢失,用户每次回来都要重新设置。
- **影响**:未验证前是隐患;若确认丢失,核心流程体验断裂。
- **改法**:先验证 shell 挂载策略;若卸载,把 filter/view/search/page/pageSize/collapsed 提升到模块级 store 或 sessionStorage,返回后还原(搜索/展开属会话内状态,可仅存于内存)。
- **工作量**:中(验证为小,实现为中)

### B15. 分组视图表格无列头
- **位置**:DashboardView.tsx:875-876(`<table className="dshd-table"><tbody>…</tbody></table>`,无 thead)
- **现象**:"按轮次/按模型/按错误"视图的行复用 renderRow,但整张表没有 `<thead>`,列没有标签——用户看到一排数字(输入/输出/耗时/状态)无法对应。
- **影响**:三个分组视图的数字列不可解读,是信息架构的明显缺口(表格视图有表头,同一区块内体验分裂)。
- **改法**:分组视图渲染与表格相同的 thead(列数一致:chevron/#/轮步/模型/输入/输出/耗时/状态[/跳转])。
- **工作量**:小

## 第二部分:新建议(按收益/成本排序,TOP 5 标 ★)

### ★S1. 表格列排序(收益高 / 成本小-中)
- **问题点**:找"最慢请求 / 最大输入 / 最大输出"是监控最常任务,当前只能靠 hover 逐根柱或切分组视图;表格本身不可排序。
- **具体改法**:表头可点击排序(seq / 轮步 / 模型 / 输入 / 输出 / 耗时),点击循环 升序→降序→默认;表头显示排序箭头;与筛选/搜索/分页组合生效;默认仍按"最新在前"。
- **工作量**:小-中

### ★S2. 行点击语义:展开与跳转解耦(收益高 / 成本小)
- **问题点**:成功行"整行点击=跳转",唯一展开入口是 9px 的 ▸(且键盘不可达,见 B1)。用户按表格通用心智"点行=展开"操作,却被切到轨迹视图——误触是最高频打断;两个语义绑定在同一热区,可发现性差。
- **具体改法**:默认"点击行=内联展开",跳转收敛到行尾 ↗ 按钮(双击行或 ⌘/Ctrl+点击 也可跳转);保留错误行"点击=展开错误"不变;若担心弱化"跳转"能力,可在明细区头部加"行点击行为"开关(展开 / 跳转)。
- **工作量**:小

### ★S3. 筛选与视图 Tab 计数徽标(收益高 / 成本小)
- **问题点**:状态筛选(全部/进行中/完成/失败)与视图 Tab(表格/按轮次/按模型/按错误)均无计数,用户不知道"失败几个""错误几条",只能逐个点开看。
- **具体改法**:按钮上加 `(n)` 徽标(失败/错误用语义色);随实时数据自动刷新;与 B6 的行位移修复配合,让用户一眼知道该切哪。
- **工作量**:小

### ★S4. "只看告警"模式(收益高 / 成本中)
- **问题点**:12+ 卡片平铺,实时监控时用户的核心诉求是"有没有异常",但错误数、工具错误率、上下文压力、loop/无进展、stuck 请求、超时告警散落在 6-8 张卡里,要逐卡扫。
- **具体改法**:明细区顶部加"只看告警"开关:开启后自动折叠无告警卡,仅保留含告警的卡并置顶(告警判定复用已有指标:failedRequests>0 / toolErrorCount>0 / pressure≥70% / loops / noProgress / stuckRequests / retries);开关状态与 B14 的状态持久化一起记忆;顶部加"告警摘要条"(几条告警,点击逐条跳卡)。
- **工作量**:中

### ★S5. Sticky 条内嵌横向锚点 chips + 语义着色(收益中高 / 成本小-中)
- **问题点**:页面=总览 + Token + 8~10 张网格卡 + 趋势,滚动距离极长,找"某个指标"要滚很久;且 Sticky 条只有 6 个数字,没有"现在在哪个区块"的方位感,数字也无语义着色(失败数不是红色)。
- **具体改法**:在 Sticky 汇总条右侧(或下一行)放一排横向 section 锚点 chips(总览/Token/压力/消息/耗时/工具/模型/压缩/异常/健康/趋势):点击平滑滚动到对应卡,滚动时当前 section 高亮;Sticky 数值按语义着色(失败红/进行中蓝/成本正常);形态是条内横向 chips,与已提过的"右侧竖排 mini 目录"不同,不占额外空间。
- **工作量**:小-中

### S6. 搜索增强:命中计数 + 片段高亮 + Esc 清除
- **问题点**:搜索无命中反馈弱(B4),命中行无高亮,清除要手动删词。
- **具体改法**:搜索框旁显示"x/y 条命中";命中字段片段高亮(seq/模型/错误/工具名);Esc 一键清空;输入框加清除按钮。
- **工作量**:小

### S7. 空态引导升级
- **问题点**:整页空态(hasData=false)只有一句文案(1023-1037),表格空态"暂无请求记录"无下一步引导。
- **具体改法**:空态给行动指引("前往对话页发起一条消息,指标将实时出现");表格空态注明"运行中会实时追加,点击行可跳转轨迹";区分"从未开始"与"窗口内无请求"。
- **工作量**:小

### S8. 趋势图加轴量级标签与基线
- **问题点**:SeriesBars/AreaChart 无 Y 轴刻度与最大值标注,不悬停就读不出量级;三行图表结构同构,扫读效率低。
- **具体改法**:每图标注 max 值与浅色基线网格;耗时/输入/输出图与对应 StatCard 颜色呼应(已部分一致,补齐);TTFT 图补 Y 轴单位。
- **工作量**:小

### S9. 隔离 1 秒 tick 的级联重渲染(性能/输入手感)
- **问题点**:运行中每秒 `setClock` 重渲染 DashboardView;`jumpTo` 每次渲染重建(992-1010),TrendSection 无法 memo,60 根柱×多图每秒全量 reconciliation;搜索框在 TrendSection 内(711-721),打字可能与 tick 抢帧。
- **具体改法**:`useCallback(jumpTo)` + `React.memo(TrendSection/各图表)`;把"已用时长"等每秒变化的文本收敛到 DetailPanel/stream 行局部计时器,不逐秒重渲染全树。
- **工作量**:小

### S10. 工具调用 args 溢出交互
- **问题点**:展开详情的 args 截断(224),只能 hover title 看全文,长参数无法阅读、复制。
- **具体改法**:超长 args 行内"展开/收起"或"复制"按钮(原生 `navigator.clipboard`)。
- **工作量**:小

### S11. 导出格式扩展
- **问题点**:仅 JSON;分析/分享场景不便(B5 之外的需求缺口)。
- **具体改法**:JSON 保留(含 search/view 元信息),新增 CSV(仅当前可见列+状态列);导出按钮改小菜单,复用现有逻辑。
- **工作量**:小

### S12. 偏好记忆(localStorage)
- **问题点**:pageSize、视图、搜索词、折叠状态刷新即丢(B14 是跨 tab 切换,这里是跨刷新/重开)。
- **具体改法**:pageSize/view/filter 持久化 localStorage;search/展开属会话内,保持现状或并入 B14 方案。
- **工作量**:小

## 第三部分:TOP 5 汇总与落地顺序

| 排名 | 建议 | 收益 | 成本 |
|---|---|---|---|
| 1 | ★S2 行点击语义解耦(防误触跳转) | 最高频交互的打断消除 | 小 |
| 2 | ★S3 筛选/视图计数徽标 | 一眼定位问题分布 | 小 |
| 3 | ★S1 表格列排序 | 核心排查任务提效 | 小-中 |
| 4 | ★S5 Sticky 锚点 chips + 语义着色 | 长页面导航 + 状态可读 | 小-中 |
