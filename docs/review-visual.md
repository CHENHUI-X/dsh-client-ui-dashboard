## 一、已实现但存在明显视觉缺陷(Bug 级,优先修)

### B1. `.dshd-jump` 重复 CSS 规则 → 详情面板"跳转轨迹"按钮文字溢出(工作量:小)

- **问题点**:`dashboard.css.ts` 第 306–307 行定义了胶囊按钮样式(蓝底、圆角 999px、`padding:1px 9px`),第 308–309 行**又定义了一遍同名 `.dshd-jump`**,后一条把前一条完全覆盖为 `width:24px;height:24px` 的正方形图标按钮。而 `DashboardView.tsx` 第 156–158 行详情面板的跳转按钮用的是**同一类名但内容是本地化文本** `{t("req.jumpTrajectory")} ↗`(如"跳转轨迹 ↗")——文本被塞进 24×24 的盒子,会换行/溢出,视觉上直接破相;表格行的 ↗ 图标按钮(第 383–395 行)则正常。
- **具体改法**:拆分两个语义:`dshd-jumpIcon`(24×24 方形,表格行用)与 `dshd-jumpText`(胶囊,详情面板用),删掉被覆盖的重复规则;或给表格行按钮独立类名,保留 `.dshd-jump` 为胶囊。
- **工作量**:小(两处类名 + 两条 CSS)。

### B2. 模型配色双调色板不一致 → 同一模型在两张卡里是两种颜色(工作量:小)

- **问题点**:`DashboardView.tsx` 第 55–64 行 `PALETTE` 与 `charts.tsx` 第 509–518 行 `MODEL_COLORS` 是**两份内容、顺序都不同的调色板**(PALETTE 顺序为 蓝/绿/红/琥珀+3 混色;MODEL_COLORS 为 蓝/绿/琥珀/红+3 混色+灰)。模型横条(`modelRows`,第 1076–1082 行)按 `PALETTE[i % 8]` **索引**取色,模型时间线(`ModelTimeline`)按 `modelColorHash(name)` **哈希**取色。同一个模型(尤其最常见的单模型会话)在"模型用量横条"和下方"模型时间线圆点"里大概率是两种颜色——专业监控面板的硬伤。
- **具体改法**:收敛为**一个**调色板 + 一个 `modelColor(model, index?)` 帮助函数,横条与时间线统一按 `hash(model)` 取色(横条也可退化为按索引,但必须同一数组);`MODEL_COLORS` 与 `PALETTE` 删其一,并移到共享模块。
- **工作量**:小。

### B3. 面积图边缘 tooltip 丢失垂直位移(工作量:小)

- **问题点**:`charts.tsx` `AreaChart`(第 413–427 行)在 `pos < 0.33` 或 `pos > 0.67` 时用**内联 `style.transform = translateX(-6%) / translateX(-94%)`**,内联样式整体覆盖了 CSS 类 `.dshd-areaWrap .dshd-vtip`(dashboard.css.ts 第 298 行)的 `transform:translate(-50%,calc(-100% - 6px))`。结果:图中间悬停时 tooltip 浮在数据点上方,靠近左右边缘时却**垂直居中叠在点上**、水平偏移也从 -50% 变成 -6%/-94%,同图两种对齐,视觉不一致。
- **具体改法**:内联 transform 改为合并写法(如 `translate(-6%,-100%) translateY(-6px)` 之类与类规则同构),或把水平偏移量改为 CSS 变量(`--tip-dx`)由类规则统一拼 `translate(var(--tip-dx,-50%), calc(-100% - 6px))`。
- **工作量**:小。

### B4. "运行中"状态双色并存(工作量:小)

- **问题点**:同一 running 语义用了两种颜色——头部 live 胶囊 `.dshd-live`(dashboard.css.ts 第 50 行)与直播行圆点 `.dshd-streamDot`(第 209 行)用 **success 绿**;请求表状态徽标 `.dshd-statusPill[data-s=running]`(第 134 行)用 **business 蓝**;趋势图 running 柱(`SeriesBars` data-status)脉冲但不改色。用户会困惑"运行中到底是什么颜色"。
- **具体改法**:统一为一种"进行中"语义色。建议以 business 蓝为 running 的全局色(与表内徽标、脉冲柱一致),头部 live 胶囊改用蓝;或反之全用绿,但注意绿同时是"助手/缓存命中/完成"的语义色,易混淆,故推荐前者。
- **工作量**:小。

### B5. 吸顶表头与吸顶汇总条重叠(工作量:中)

- **问题点**:`.dshd-table th`(dashboard.css.ts 第 117 行)`position:sticky;top:0;z-index:2` 与 `.dshd-summary`(第 214 行)`position:sticky;top:0;z-index:20` **钉在同一滚动口的同一位置**。滚动到明细区时,表头滑进吸顶汇总条**下方**:汇总条背景是 `88% 透明 + blur(6px)`,被盖住的表头文字会透过模糊层"幽灵般"显现,且表头实际不可见——吸顶表头功能等于失效。
- **具体改法**:(a) 简单方案:去掉 `th` 的 sticky(表格已分页 10–50 行,吸顶表头收益有限);(b) 稳妥方案:用 ResizeObserver 测汇总条高度写入 CSS 变量,`th{top:var(--dshd-summaryH,0)}`;(c) 至少给汇总条加**不透明底色 + 底部发丝线**(见 F2),消除透叠。
- **工作量**:中(取决于选 a 则小)。

### B6. 表情符号 🔁/🐢 与主题风格冲突(工作量:小)

- **问题点**:`DashboardView.tsx` 第 1563 行 `🔁 {l.name}`、第 1569 行 `🐢 {t("hint.noProgress")}` 用彩色 emoji,而全站是克制的中性 token 配色 + 文本字形(↗ ▸ ‹ › × ·)。emoji 渲染随操作系统变化,在深色主题下高饱和色块会破坏整体质感,与 ⚠(第 331 行,部分平台也渲染为 emoji)混用后风格更乱。
- **具体改法**:换为单色文本徽标或 SVG 图标(如小圆点 + 文本",循环" / ",无进展"),或复用 `.dshd-tag[data-k=...]` 的 tinted 胶囊样式;全站错误/告警符号统一走同一种 ⚠ 字形并确保文本渲染。
- **工作量**:小。

## 二、配色一致性

### C1. 同语义跨卡配色漂移:工具/耗时/推理(工作量:小)

- **问题点**:三个概念在不同卡里颜色不一致——
  - **工具**:上下文构成里 `CHART_COLORS.tools` = **红**(第 36 行);耗时卡堆叠条 `toolTime` = **琥珀**(第 34 行);工具直方图与耗时 Top 却用 `PALETTE` **任意轮转色**(第 1068–1074、1427–1434 行);工具风暴柱也用琥珀。同一"工具"概念三处三色。
  - **耗时**:Timing 卡堆叠条是 蓝/琥珀;趋势卡 duration 柱是 `CHART_COLORS.reasoning`(红-琥珀混色,第 473 行);TTFT 面积图同样用 reasoning 混色。用户在"耗时"和"TTFT"之间找不到共同锚点。
  - **推理**:reasoning 混色同时用于推理 token、时长、TTFT、推理占比、直方图,语义过载。
- **具体改法**:给"工具"定一个主语义色(建议琥珀=工具执行,与 timing 卡一致,把上下文构成里的 tools 从红改为琥珀,红只留给输出/错误);"耗时"系(时长/TTFT/直方图)统一用一个专属色(可用现有 reasoning 混色,但 TTFT 与时长在图例上要有区分,比如 TTFT 用混色、时长用纯琥珀的明度变体);在 `CHART_COLORS` 顶部加注释表"概念→颜色"防止再次漂移。
- **工作量**:小。

### C2. 环形图单段特例:只剩一个角色时出现 15px 缝隙(工作量:极小)

- **问题点**:`DonutChart`(charts.tsx 第 58–142 行)无论段数都预留 `n` 个 `gap = thickness`(第 75–96 行)。当消息构成只有 1 个角色(如纯 assistant 会话)时,单段弧长为 `C - gap`,圆环上留一道 15px 的明显缺口,看起来像渲染 bug。
- **具体改法**:`n === 1` 时特判为整圆(`strokeDasharray = C 0`,offset 0),保留 minLen 逻辑只用于多段。
- **工作量**:极小。

## 三、图表细节

### D1. 迷你趋势图加"右端终值标签 + 最大参考线"(工作量:小)

- **问题点**(收益高):趋势区 10 张小图(`AreaChart`/`SeriesBars`,高 60–76px)全部**无坐标轴、无刻度、无终值标注**,只能悬停读单点;滚动快速扫读时完全无法估读量级——监控类看板的核心诉求是"扫一眼知道数值和走势"。
- **具体改法**:给每张小图右侧加终值标签(面积图:最后一个点的值以 9–10px 胶囊浮在右端;柱状图:最大值柱顶标注),或在图底加一条淡色最大值虚线(`--dsw-alias-border-l1`,opacity .5)。`dshd-seriesCol` 内新增 `.dshd-chartEndTag` 即可,零新依赖。P50/P95/P99 行(第 602–607 行)已示范了"把关键数放图内"的正确思路,可推广。
- **工作量**:小。

### D2. 图例 ↔ 环形图 hover 联动(工作量:中)

- **问题点**:`Legend`(charts.tsx 第 145–167 行)与 `DonutChart` 各自独立管理 hover,图例悬停无任何反馈,环形图悬停段也不高亮对应图例行——两个信息源无法互指,环形图 hover 的"扩径+中心数值"设计因此只发挥了一半。
- **具体改法**:给 `LegendRow` 加 hover 态(淡 tinted 底色 + 色点放大),通过共享 `hover` state(把 hover 状态提升到 `dshd-donutRow` 容器或给 DonutChart/Legend 传 `onHover` 回调)实现双向联动;段透明度淡化逻辑复用现有 `opacity .45`。
- **工作量**:中。

### D3. 模型时间线:基线轨 + 悬停放大 + 切换点增强(工作量:小)

- **问题点**:`ModelTimeline`(charts.tsx 第 530–598 行)60 个点、`step = 7px`、r=3,密时几乎连成一条彩带,看不出时间顺序与间隔;切换点只有 1.2px 琥珀描边,与普通点区分度不足;hover 无任何放大/描边反馈(仅原生 title)。
- **具体改法**:① 加一条 1px 淡色基线(`--dsw-alias-border-l1`,位于 cy)让"无点处=空档"可读;② 切换点描边加粗到 2px 并 `r:4`,普通点 hover 时 `r:4.5 + 主题色描边`(CSS 变量过渡即可);③ 可选:末尾加"最新"箭头标记。
- **工作量**:小。

### D4. 直方图基线对齐(工作量:极小)

- **问题点**:`.dshd-hist`(dashboard.css.ts 第 236–238 行)高 52px、`align-items:flex-end`,柱底紧贴容器底,无基线;0 值桶只有 1px 高的色条残留(第 238 行 `min-height:2px` + 高度 2%),密集时长尾桶看起来是"一排噪点底噪"。
- **具体改法**:容器加 1px 底部基线(`border-bottom:1px solid var(--dsw-alias-border-l1)`),0 值桶不渲染(高度 0)。
- **工作量**:极小。

### D5. 行级 hover 反馈统一:hbar / turnRow / errRow / legendRow(工作量:小)

- **问题点**(收益高):表格行(`.dshd-table tbody tr:hover`)、分组头、柱状图、过滤按钮都有 hover 反馈,但**横向条行**(`.dshd-hbar`,第 105 行)、**轮次行**(`.dshd-turnRow`,第 253 行)、**错误/命令/压缩/强度行**(`.dshd-errRow`/`.dshd-compactRow`,第 241/246 行)、**图例行**(`.dshd-legendRow`,第 86 行)全部没有任何 hover 视觉——它们恰恰都带 `title` 提示,用户悬停意图明确却得不到视觉确认。
- **具体改法**:统一加 `:hover{background:var(--dsw-alias-interactive-bg-hover)}` + `border-radius:6px`(行内 padding 2px 4px 负边距补偿,参考 `.dshd-chevron` 的 margin 技巧),图例行 hover 配合 D2 联动。
- **工作量**:小。

## 四、层级、密度与留白

### H1. 卡片标题分级:语义色 accent 条 + 分区标签(工作量:小)

- **问题点**(收益高):`.dshd-cardTitle::before`(dashboard.css.ts 第 63 行)给 **12+ 张卡全部**画同一条 3px 灰色竖条,没有携带任何信息;标题统一 13px/600,卡片间无主次。12 张卡平铺时,用户只能靠读文字找区块,视觉疲劳来源之一。
- **具体改法**:① 竖条按卡语义着色:总览/模型/趋势→business 蓝、上下文压力/压缩/注入→warn 琥珀、异常/健康/错误→error 红、Token/缓存→success 绿(示例映射,与 CHART_COLORS 语义对齐);② 卡片簇之间加 10px 字号的分区标签(如"上下文 / 质量 / 明细",复用 `.dshd-subTitle` 视觉),把平铺切成 3–4 个可扫读的组——纯视觉补充,不重复架构报告的"三层视图"方案。
- **工作量**:小。

### H2. 明细区双控件行合并(工作量:中)

- **问题点**:`dshd-viewTabs`(4 个 Tab,第 675 行)+ `dshd-filters`(4 个筛选胶囊 + 搜索框 + 导出,第 694–725 行)纵向叠成**两整行控件带**,视觉重量超过其信息量;两行按钮高度都是 24px、风格相近(圆角胶囊),用户需仔细分辨"Tab 和筛选"的分工。
- **具体改法**:合并为单行分段控件:Tab 用下划线式(去掉药丸底),筛选/搜索/导出保留胶囊;或 Tab 行收纳到卡片标题右侧(`dshd-cardHead` 内),筛选行独占一行。任一方案都能省出一行留白。
- **工作量**:中。

### H3. 统计卡"卡中卡"弱化(工作量:小)

- **问题点**:`.dshd-stat`(第 71 行)`bg-base + 1px 边框` 嵌在 `.dshd-card`(`bg-layer-1 + 1px 边框`)里,12–16 张小卡 = 每个都自带一圈描边,叠加后视觉噪点多;且 `dshd-stat:hover` 的 `translateY(-1px)`(第 72 行)让整块卡片在 hover 时"跳动",与表格行 hover 的克制风格不一致。
- **具体改法**:统计卡去掉边框,仅保留底色差异 + hover 时 `background:var(--dsw-alias-interactive-bg-hover)` 圆角 12px;去掉 translateY,或保留但缩小为背景色过渡。
- **工作量**:小。

### H4. `dshd-grid2` 列数钉住 2 列,避免 auto-fit 破坏配对(工作量:小)

- **问题点**:`.dshd-grid2{grid-template-columns:repeat(auto-fit,minmax(320px,1fr))}`(第 65 行)。根容器 max-width 1120 − padding 36 = **1084px 内容宽**时,auto-fit 算出 **3 列**(每列约 350px),JSX 中按"两两配对"写的卡(上下文压力+注入来源、消息+耗时、轮次+工具、模型+异常……)被拆散;上下文压力卡的 `dshd-gaugeRow`(148px 半圆仪表 + 堆叠条)在 350px 宽下被迫换行,仪表盘与构成条上下堆叠,正是该卡最不该发生的布局。
- **具体改法**:改为 `grid-template-columns:repeat(2,minmax(0,1fr))`,窄屏(<760px)媒体查询降为 1 列;同时按"每行两张卡高度相近"重新排 JSX 顺序(当前顺序已基本配对,钉 2 列即可)。
- **工作量**:小。

### H5. "?" 提示密度治理(工作量:小)

- **问题点**:`Hint` 组件(第 67–73 行)在总览 + Token 卡里出现约 17 个 14px 圆圈"?"(turns/steps/requests/tools/compactions/cost/totalDuration/avgTtft/decodeSpeed/input/output/reasoning/cacheHitRate/contextOccupancy/contextInjection……),一排卡片里密密麻麻的灰色小圆,本身就成了视觉噪声,弱化了真正重要的数字。
- **具体改法**:① 标签改为"虚线点状下划线 + 悬停 title"(`text-decoration:underline dotted`,颜色 label-tertiary),无图标;② 或图标化:单个 12px 内联 SVG help 图标、`opacity:.6`,悬停才提亮;③ 若保留圆形,统一用 `--dsw-alias-bg-base` 底 + 更浅边框、字号降到 9.5px。
- **工作量**:小。

## 六、细节打磨

### N1. 轴提示文案去重(工作量:极小)

- **问题点**:每张小图下都重复渲染"最新在右 · 仅最近 60 条"(第 547/556/565/582/601/624/642/651 行等约 10 处),10px 灰字连成一条"地毯",翻倍了视觉噪音。
- **具体改法**:提示只在趋势区**首图或末图**出现一次,或移到 `dshd-seriesRow` 行级右侧统一渲染;TTFT 分位数、压缩标记这类**有信息量**的注记保留原位。
- **工作量**:极小。

### N2. 成本金额自适应小数位(工作量:极小)

- **问题点**:`.dshd-statValue` 与汇总条统一等宽数字,但成本 `toFixed(4)`(第 1219/1141 行)在小额时是 `$0.0002`,4 位小数在大字号等宽字体下偏长;大额时 `$12.3456` 又显得精度过剩。
- **具体改法**:按量级自适应(≥1 时 2–3 位、<1 时 4 位或去尾零),并让 `$` 与数字间不留空隙(`$${...}` 已是),保持 tabular-nums 对齐。
- **工作量**:极小。

### N3. 表格横向滚动提示(工作量:小)

- **问题点**:`.dshd-table` `min-width:640px` + `overflow-x:auto`(第 115–116 行),窄容器下右侧列被截断且**无任何滚动暗示**(无渐变、无阴影、无"更多列"提示),用户可能根本没发现还有"模型/状态/跳转"列。
- **具体改法**:`.dshd-tableWrap` 加右侧 12px 淡出遮罩(`mask-image:linear-gradient(90deg,#000 calc(100% - 24px),transparent)`),滚动到末尾自动消失;或加 `scrollbar-width:thin` + 可滚动时右下角小箭头。
- **工作量**:小(有滚动监听则为中)。

### N4. tag 与 statusPill 视觉统一(工作量:小)

- **问题点**:详情面板头部同时出现 `.dshd-tag`(第 153 行,仅描边无底色,文本色为混色/琥珀/红)与 `.dshd-statusPill`(第 132–136 行,tinted 底色 + 描边 + 圆角胶囊),两个"小标签"体系并排,视觉权重不一致。
- **具体改法**:统一为 statusPill 的 tinted 胶囊风格(reasoning/compaction/error 三种 tag 各配 12% tint 底色),或统一为 tag 的描边风格;二选一即可。
- **工作量**:小。
