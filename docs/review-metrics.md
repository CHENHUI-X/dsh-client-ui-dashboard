# DSH 对话看板插件 · 指标补全建议清单(完整评估报告)

> 说明:本次调研中 `web_search` 工具持续返回 API key 认证错误,未能联网取证;以下基于对 LangSmith、Langfuse、Helicone、Arize Phoenix、W&B Weave、OpenLLMetry、OTel GenAI 语义约定、AgentOps、Braintrust、Literal AI、HoneyHive、Langtrace 及 Grafana 社区 LLM 面板公开指标体系的既有知识整理。每条含:名称 / 价值 / 数据可得性 / 展示建议 / 工作量(小·中·大)。均已核对与现有功能不重复。

---

## 1. 成本估算(Cost Estimation)

- **价值**:Agent 落地第一痛点,PM/工程最关心单轮成本、会话累计成本、模型切换后的成本变化;LangSmith/Helicone/Langtrace 均内置成本跟踪。
- **数据可得性**:高。配置模型定价表(按模型 × token 类型:输入 / 缓存读取 / 缓存写入 / 输出)后,由已有 token 计数直接算出;DeepSeek 价目公开可查。
- **展示建议**:按模型/工具分组的成本瀑布图 + 累计成本面积图;请求明细表加成本列。
- **工作量**:中(需维护定价表)。

## 2. 延迟拆解(Latency Breakdown: Queue vs TTFT vs Decode)

- **价值**:TTFT 高是排队还是首字慢?解码慢是模型问题还是输出过长?对齐 OTel `gen_ai.client.operation.duration` 的 phase 语义(排队/系统/用户/最终响应)。
- **数据可得性**:部分。排队时间需在请求入队处额外打点(框架侧可加);TTFT 与解码部分基于现有数据可算。
- **展示建议**:排队/首字/解码/工具四段堆叠条 + 各阶段 P50/P95 对比。
- **工作量**:中。

## 3. 缓存经济性(Cache Economics)

- **价值**:缓存命中率已有,但"命中缓存省了多少钱/多少时间"更打动决策者;Helicone 缓存产品与 DeepSeek 折扣定价均支撑此指标。
- **数据可得性**:高(需与定价表配合)。
- **展示建议**:缓存节省成本累计曲线 + cache-hit 与 cache-miss 的 TTFT 箱线对比。
- **工作量**:小。

## 4. 吞吐与速率(Throughput)

- **价值**:评估会话是否卡顿、模型服务吞吐;已有解码速度,缺请求/分钟与 token/分钟级速率曲线。
- **数据可得性**:高(全部可从事件流与时间戳聚合)。
- **展示建议**:趋势区加 RPM(请求/分钟)、token/min 曲线、并发请求数。
- **工作量**:小。

## 5. 完成原因分布(Finish Reason)

- **价值**:stop / length / tool_calls / content_filter 分布,量化 max-tokens 截断造成的 token 浪费(输出触顶已有计数,缺浪费量)。
- **数据可得性**:高(响应元数据含 finish_reason)。
- **展示建议**:环形图 + "截断浪费 tokens"数字卡。
- **工作量**:小。

## 6. 重试/回退率(Retry & Fallback Rate)

- **价值**:异常页有重试次数,缺比率与回退路径;区分"失败回退"与"主动切换"。
- **数据可得性**:高(事件流含重试/模型切换事件)。
- **展示建议**:重试率 = 重试请求 / 总请求,按模型分;模型切换中标注原因(失败回退 vs 主动)。
- **工作量**:小。

## 7. 循环检测(Loop Detection)

- **价值**:Agent 典型故障——同工具同参数重复调用、轮次循环空转;AgentOps/Braintrust 均关注此类行为指标。
- **数据可得性**:高(事件流含工具名 + 参数)。
- **展示建议**:连续 ≥3 次相同 tool+args 高亮;循环轮次在时间线上标记。
- **工作量**:中。

## 8. 无进展检测(No-Progress)

- **价值**:低 token 产出 + 高工具调用 = 空转,识别"看似忙碌实则死循环"的会话。
- **数据可得性**:高。
- **展示建议**:每轮新增 token 散点图,低于阈值的轮次标红。
- **工作量**:小。

## 9. 工具风暴(Tool Storm)

- **价值**:单位窗口内工具调用过密导致成本与延迟失控。
- **数据可得性**:高。
- **展示建议**:工具调用频率曲线(次/分钟)+ 阈值告警。
- **工作量**:小。

## 10. 上下文演变(Context Evolution,锯齿曲线)

- **价值**:压缩功能已有单次前后对比,缺"窗口增长斜率 → 预测下次压缩时机"的整体演变视图。
- **数据可得性**:高(压缩事件与上下文压力数据均在)。
- **展示建议**:上下文大小随轮次锯齿图 + 压缩标记 + 距上限余量迷你图。
- **工作量**:小。

## 11. 模型切换模式(Model Switching Pattern)

- **价值**:切换是失败回退还是策略选择?对成本与质量影响大。
- **数据可得性**:高(模型切换次数已有,缺模式视图)。
- **展示建议**:模型泳道时间线(每轮色块)+ 切换原因标注 + 模型占比堆积。
- **工作量**:小。

## 12. 会话瀑布时间线(Waterfall)

- **价值**:把"逐轮耗时"升级为"用户消息→思考→工具→输出"瀑布,一眼定位瓶颈。
- **数据可得性**:高(节点级事件流 + 每轮耗时)。
- **展示建议**:横向瀑布图,工具调用内嵌,点击跳转请求详情。
- **工作量**:中。

## 13. 会话对比/回放(Compare & Replay)

- **价值**:压缩前后、模型 A/B 双跑对比,复盘行为差异。
- **数据可得性**:高(快照/导出能力支撑)。
- **展示建议**:双列时间线 diff;step 步进回放。
- **工作量**:大。

## 14. 导出与快照(Export & Snapshot)

- **价值**:排查上下文共享、审计归档;LangSmith 分享链接、Langfuse 导出均为此类。
- **数据可得性**:高。
- **展示建议**:导出 JSON/Markdown/HTML 报告按钮;时间点快照 diff(指标前后对比)。
- **工作量**:小。

## 15. 反馈与评分(Feedback & Eval)

- **价值**:用户对助手消息点赞/点踩 + LLM-as-judge 自评(Phoenix、Literal AI 主打)。
- **数据可得性**:中(反馈需插件埋点采集,评分需调用评测)。
- **展示建议**:消息行内反馈按钮 + 评分趋势,低分轮次标注。
- **工作量**:中。

## 16. 会话级 KPI(Per-Session KPI)

- **价值**:整个任务的"性价比":总时长 / 总成本 / 步数 / 完成状态。
- **数据可得性**:高(均为已有数据聚合)。
- **展示建议**:会话头部 KPI 卡组。
- **工作量**:小。

## 17. Token 效率(Token Efficiency)

- **价值**:每轮输入增长是否合理,输出/输入比低 = 上下文膨胀。
- **数据可得性**:高。
- **展示建议**:每轮新增 token 分布图(现有增量徽标升级为分布)+ 单次工具调用平均 token 成本。
- **工作量**:小。

## 18. 异常检测与告警(Anomaly & Alerts)

- **价值**:超时告警已有,扩展为 TTFT/耗时突刺(z-score)、错误率阈值、预算告警。
- **数据可得性**:中(需规则配置)。
- **展示建议**:突刺标记 + 可配置告警规则(预算上限、错误率、无进展)。
- **工作量**:中。

## 19. 提供商错误归因(Provider Attribution)

- **价值**:多 provider 场景区分网络错误 / 限流(429)/ 服务端错误。
- **数据可得性**:高(错误事件含 provider 与状态码)。
- **展示建议**:错误按 provider 堆积 + 限流重试事件标记。
- **工作量**:小。

---

## TOP 10 高价值小结

1. **成本估算(含缓存节省)** — 决策刚需,立即补。
2. **循环/无进展检测** — Agent 特有故障,先做小版本。
3. **延迟拆解(排队/TTFT/解码)** — 排查利器,对齐 OTel 语义。
4. **上下文锯齿曲线 + 压缩预测** — 贴合现有压缩功能,增量小。
5. **模型切换模式时间线** — 成本/质量归因。
6. **工具风暴频率** — 成本失控预警。
7. **完成原因分布(截断浪费)** — 量化 token 浪费。
8. **会话瀑布时间线** — 可视化升级,定位瓶颈。
9. **重试/回退率** — 与现有异常页互补。
10. **导出/快照** — 成本低、协作与审计价值高。
